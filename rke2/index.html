Instalar Kubernetes con RKE2

Tutorial breve por línea de comandos para montar un clúster RKE2 (la distribución de Kubernetes de Rancher/SUSE) con 1 server y 2 agents. Cada comando indica en qué nodo se lanza. ¿Vienes de kubeadm? Mira el tutorial de kubeadm y la comparativa de abajo.

Resumen en 5 esquemas

① Los nodos · en RKE2 el master se llama server y los workers, agents

② Los pasos · gris = todos los nodos · morado = server · verde = agents

③ Quién arranca qué · ámbar = procesos (servicio systemd y sus hijos) · azul = static pods

④ Plano de control y plano de datos

ℹ️ Nota: el server también ejecuta containerd, kubelet, kube-proxy y Canal, como cualquier nodo; y por defecto sí acepta pods de aplicaciones, a diferencia de kubeadm.

El clúster que vamos a montar

■ Proceso: servicio systemd o hijo de rke2 ■ Static pod: lo arranca el kubelet desde un YAML local ■ Pod normal: lo arranca el kubelet por orden del apiserver

La gran diferencia con kubeadm es que en cada nodo solo hay un servicio de systemd: rke2-server o rke2-agent. Ese proceso hace de supervisor: arranca containerd y el kubelet como procesos hijos (los reinicia si se caen) y escribe los manifiestos de los static pods. Compruébalo con systemctl status rke2-server: verás containerd y kubelet colgando de él.

¿Quién arranca a quién?

¿Quién lee /var/lib/rancher/rke2/agent/pod-manifests? El kubelet de cada nodo, igual que en kubeadm. La diferencia es quién escribe los YAML: aquí es el propio rke2-server (o rke2-agent, que solo escribe el de kube-proxy).

¿Qué es el helm-controller? Un controlador integrado en rke2-server. Al arrancar, RKE2 deja unos charts de Helm en /var/lib/rancher/rke2/server/manifests/, y el helm-controller los instala en el clúster a través del apiserver. Así llegan Canal, CoreDNS, el ingress y metrics-server sin que tengas que hacer nada.

🖥️ Todos los nodos

Paso 1. Preparar el sistema

[ SERVER ✔ ]   [ AGENT 1 ✔ ]   [ AGENT 2 ✔ ]
hostnamectl            # cada nodo debe tener un nombre distinto
sudo systemctl disable --now firewalld   # si existe (RHEL/Rocky); en Ubuntu, ufw: sudo ufw disable

Cada nodo necesita un hostname único, porque es el nombre con el que se registra en el clúster. Desactivar el cortafuegos evita bloqueos entre nodos (o abre al menos los puertos 9345, 6443, 10250 y 8472/udp).

# Solo si el sistema usa NetworkManager:
cat <<EOF | sudo tee /etc/NetworkManager/conf.d/rke2-canal.conf
[keyfile]
unmanaged-devices=interface-name:flannel*;interface-name:cali*;interface-name:tunl*;interface-name:vxlan.calico;interface-name:vxlan-v6.calico;interface-name:wireguard.cali;interface-name:wg-v6.cali
EOF
sudo systemctl reload NetworkManager

Le dice a NetworkManager que no toque las interfaces virtuales que crea Canal, la red de pods de RKE2. Si no, puede "reconfigurarlas" y romper la red de los pods.

Comparado con kubeadm: aquí no hace falta tocar la swap, ni cargar módulos del kernel, ni instalar containerd ni añadir repositorios. RKE2 lo trae todo.

👑 Solo server

Paso 2. Instalar RKE2 en el server

get.rke2.io ──descarga──▶ binario rke2 + servicio rke2-server
curl -sfL https://get.rke2.io | sudo sh -

Descarga e instala el binario rke2 y crea el servicio de systemd rke2-server. Ese único binario contiene containerd, el kubelet y las imágenes del plano de control. Para fijar una versión concreta, añade INSTALL_RKE2_VERSION="v1.xx.x+rke2r1" o INSTALL_RKE2_CHANNEL="stable" antes de sh -.

👑 Solo server

Paso 3. Arrancar el server

systemd ─▶ rke2-server ─▶ containerd + kubelet ─▶ static pods ─▶ charts
sudo systemctl enable --now rke2-server.service

Activa el servicio para que arranque con el sistema y lo inicia. La primera vez tarda unos minutos: rke2-server arranca containerd y el kubelet, escribe los manifiestos de etcd, kube-apiserver, scheduler, controller-manager y kube-proxy, y cuando el apiserver responde, el helm-controller instala Canal, CoreDNS, el ingress y metrics-server.

sudo journalctl -u rke2-server -f

Muestra el log en directo para seguir el arranque. Sal con Ctrl+C.

👑 Solo server

Paso 4. Configurar kubectl y obtener el token

/etc/rancher/rke2/rke2.yaml  →  credenciales de kubectl
/var/lib/rancher/rke2/server/node-token  →  llave para unir nodos
mkdir -p ~/.kube
sudo cp /etc/rancher/rke2/rke2.yaml ~/.kube/config
sudo chown $(id -u):$(id -g) ~/.kube/config
echo 'export PATH=$PATH:/var/lib/rancher/rke2/bin' >> ~/.bashrc && source ~/.bashrc

RKE2 escribe el kubeconfig en /etc/rancher/rke2/rke2.yaml y deja kubectl, crictl y ctr en /var/lib/rancher/rke2/bin, que no está en el PATH. Estos comandos copian las credenciales a tu usuario y añaden esa carpeta al PATH.

sudo cat /var/lib/rancher/rke2/server/node-token

Muestra el token que necesitarán los agents para unirse. Cópialo para el paso 6.

⚙️ Solo en cada agent

Paso 5. Instalar RKE2 en modo agent

get.rke2.io ──INSTALL_RKE2_TYPE=agent──▶ binario rke2 + servicio rke2-agent
curl -sfL https://get.rke2.io | sudo INSTALL_RKE2_TYPE="agent" sh -

Es el mismo instalador, pero con INSTALL_RKE2_TYPE="agent" crea el servicio rke2-agent en lugar de rke2-server. Un agent solo ejecuta containerd, el kubelet y kube-proxy: no tiene plano de control.

⚙️ Solo en cada agent

Paso 6. Decirle al agent dónde está el server

[ AGENT ] ──https://IP_SERVER:9345 + token──▶ [ SERVER ]
sudo mkdir -p /etc/rancher/rke2
cat <<EOF | sudo tee /etc/rancher/rke2/config.yaml
server: https://<IP_SERVER>:9345
token: <TOKEN_DEL_PASO_4>
EOF

Crea el fichero de configuración del agent. server es la dirección del server en el puerto 9345, que es el puerto de registro de RKE2; la API de Kubernetes sigue en el 6443. token es la llave del paso 4. Este fichero sustituye al kubeadm join.

⚙️ Solo en cada agent

Paso 7. Arrancar el agent

systemd ─▶ rke2-agent ─▶ containerd + kubelet ─▶ se registra en el server
sudo systemctl enable --now rke2-agent.service
sudo journalctl -u rke2-agent -f

Arranca el agent, que lee config.yaml, se presenta al server con el token, recibe sus certificados y arranca su kubelet. A partir de ahí el server puede mandarle pods.

👑 Solo server

Paso 8. Comprobar que todo funciona

kubectl get nodes

Todos los nodos deben aparecer en estado Ready:

NAME      STATUS   ROLES                VERSION
server    Ready    control-plane,etcd   v1.xx.x+rke2r1
agent1    Ready    <none>               v1.xx.x+rke2r1
agent2    Ready    <none>               v1.xx.x+rke2r1
kubectl get pods -n kube-system

Verás los static pods con el nombre del nodo al final (etcd-server, kube-apiserver-server, kube-proxy-agent1…), los pods de los charts (rke2-canal-…, rke2-coredns-…) y unos pods helm-install-rke2-… en estado Completed: son los trabajos con los que el helm-controller instaló cada chart.

💡 Desinstalar. El instalador deja scripts para limpiar un nodo: sudo /usr/local/bin/rke2-uninstall.sh (o rke2-killall.sh para solo parar todos los procesos y contenedores).
📌 Alta disponibilidad. Para tener varios servers, en los servers adicionales instala sin INSTALL_RKE2_TYPE y pon el mismo config.yaml (server + token). El número total de servers debe ser impar (1, 3, 5…) para que etcd mantenga el quórum.
