Instalar Kubernetes con kubeadm

Tutorial breve por línea de comandos para montar un clúster con 1 master y 2 workers en Ubuntu/Debian. Cada comando indica en qué nodo se lanza.

El clúster que vamos a montar

Orden de los pasos y dónde se ejecutan

🖥️ Todos los nodos 👑 Solo master ⚙️ Solo workers
🖥️ Todos los nodos

Paso 1. Preparar el sistema

[ MASTER ✔ ]   [ WORKER 1 ✔ ]   [ WORKER 2 ✔ ]
sudo swapoff -a
sudo sed -i '/ swap / s/^/#/' /etc/fstab

Desactiva la swap ahora y también tras reiniciar. El kubelet no arranca con la swap activada, porque necesita controlar la memoria con precisión.

cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter

Carga dos módulos del kernel: overlay, el sistema de ficheros por capas de los contenedores, y br_netfilter, que hace que iptables vea el tráfico de los puentes de red de los pods.

cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sudo sysctl --system

Activa el reenvío de paquetes (IP forwarding) y el filtrado en los puentes, para que el tráfico circule entre pods y entre nodos.

🖥️ Todos los nodos

Paso 2. Instalar el runtime de contenedores (containerd)

kubelet ──ordena──▶ containerd ──arranca──▶ 📦 contenedores
sudo apt-get update && sudo apt-get install -y containerd

Instala containerd, el programa que descarga las imágenes y ejecuta los contenedores.

sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl restart containerd && sudo systemctl enable containerd

Genera la configuración por defecto y activa SystemdCgroup, para que containerd y el kubelet gestionen los recursos (cgroups) de la misma forma. Después reinicia el servicio y lo configura para que arranque con el sistema.

🖥️ Todos los nodos

Paso 3. Instalar kubeadm, kubelet y kubectl

HerramientaPara qué sirve
kubeadmMonta el clúster (init / join)
kubeletAgente que vive en cada nodo y arranca los pods
kubectlTu “mando a distancia” para manejar el clúster
K8S=v1.34   # cámbialo por la versión estable actual
sudo apt-get install -y apt-transport-https ca-certificates curl gpg
sudo mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL https://pkgs.k8s.io/core:/stable:/$K8S/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/$K8S/deb/ /" | sudo tee /etc/apt/sources.list.d/kubernetes.list

Añade el repositorio oficial de Kubernetes y su clave de firma.

sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl

Instala las tres herramientas y las bloquea con hold, para que un apt upgrade no las actualice por su cuenta y rompa el clúster.

👑 Solo master

Paso 4. Inicializar el clúster

[ MASTER ]  ← kubeadm init crea aquí el "cerebro":
              apiserver + etcd + scheduler + controller-manager
sudo kubeadm init --pod-network-cidr=10.244.0.0/16

Crea el control-plane: genera los certificados, arranca los componentes del master y define el rango de IPs de los pods (el que usa Flannel). Al terminar muestra un comando kubeadm join …: cópialo, porque lo necesitarás en el paso 6.

mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

Copia las credenciales de administrador a tu usuario para que kubectl pueda hablar con el clúster sin usar sudo.

👑 Solo master

Paso 5. Instalar la red de pods (Flannel)

📦 pod ◀═══ Flannel ═══▶ 📦 pod
(nodo A)               (nodo B)
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml

Despliega Flannel, que crea una red virtual para que los pods se comuniquen aunque estén en nodos distintos. Mientras no haya red de pods, los nodos aparecen como NotReady. Como Flannel es un DaemonSet, se instala solo en los workers cuando estos se unen.

⚙️ Solo en cada worker

Paso 6. Unir los workers al clúster

[ WORKER 1 ] ──join──▶ [ MASTER ] ◀──join── [ WORKER 2 ]
sudo kubeadm join <IP_MASTER>:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>

Conecta el worker al apiserver (puerto 6443). El token sirve para autenticarse y el hash garantiza que el worker se une al master correcto.

👑 Solo master Si perdiste el comando, genera uno nuevo:

kubeadm token create --print-join-command
👑 Solo master

Paso 7. Comprobar que todo funciona

kubectl get nodes

Lista los nodos. Todos deben aparecer en estado Ready:

NAME      STATUS   ROLES           VERSION
master    Ready    control-plane   v1.34.x
worker1   Ready    <none>          v1.34.x
worker2   Ready    <none>          v1.34.x
kubectl get pods -A

Muestra los pods del sistema (coredns, flannel, kube-proxy…). Todos deberían estar en estado Running.

💡 ¿Solo tienes un nodo? Por defecto el master no ejecuta pods de aplicaciones. Para permitirlo, lanza esto en el master: 
kubectl taint nodes --all node-role.kubernetes.io/control-plane-
📌 Versión. Antes de empezar, consulta la versión estable actual en kubernetes.io/releases y ponla en la variable K8S= del paso 3.
